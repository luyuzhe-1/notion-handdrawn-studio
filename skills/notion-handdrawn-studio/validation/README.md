# 验证说明

仅在验证或更新 skill 时读取，本目录不参与普通生成提示词。

## 验证集

[cases.json](cases.json) 固定 12 个用户层面的请求：4 个真实生成自测（S03–S06），4 个规则走查（S01、S02、S07、S08），4 个留给用户的验证案例（H01–H04）。同一个请求保持固定，生成构图不固定，不用参考图的现成场景作为唯一答案。

规则走查检查任务边界与计划，不能证明工具运行和视觉质量；真实出图必须查看实际结果、透明通道与用途要求。用户案例在自测中不生成，不标为通过。

## 记录方式

每次记录：案例 ID、日期、skill 版本或文件哈希、请求、真实使用的提示词、参考 ID、工具、生成文件、检查证据、已知限制、是否修改。分别标记静态检查、规则走查、真实生成自评与用户评价。

## 判定

硬性要求单独判断：主体／文字／背景错误、明确的肢体或遮挡问题、Logo 缩小后不可辨认，均需调整。对于已生成样例，风格、构图和趣味各用 0–2 的自评分辅助比较：0 明显不符，1 可用但需要调整，2 基本符合。本量表只用于记录，没有统计意义，不等于用户认可。

透明检查要读取 alpha 并确认外围透明；仅存在 alpha 通道不算合格。Logo 检查 32/64/128px 缩略图的主形状与空隙。纯规则走查不能替代这些检查。

## 用户参与

先请用户看 S03–S06 的真实结果，分别反馈“可用／需要调整”、喜欢或不喜欢的具体位置及最需要改的一项。H01–H04 提供新主题，用户可以选择一个或给自己的内容来再验证。用户实际评价前保持 pending；不能把无回复视作通过。

## 修订范围

根据真实失败或用户反馈修订相关模式，保留原版本与变更依据。修订后只重跑受影响案例及一个相邻场景；不要为了匹配评分新增普遍限制。语法验证通过也不能宣称视觉验证完成。

## 人物回归

新增的 [regression-cases.json](regression-cases.json) 保留用户提出的黑板写题与浇花主题，用于人物规则修订后的两个独立新图。原 12 例及 H01–H04 保持不变。两例使用同版人物造型基准，只替换主题段，不互相输入生成结果。

保留第一次输出，先检查大形、细节、动作关系，再决定是否需要一次针对性编辑。版本记录列明各例首图、修订图、参考输入方式和未解决项；编辑成功不能回填首图为通过。若两例表现不一致，说明一致性尚未建立，不因部分改善宣称稳定。
